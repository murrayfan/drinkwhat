## 2. 安裝與本機開發

```bash
cd drink-spinner
pnpm install
cp .env.example .env.local   # 填入聯絡信箱，見第 4 節
pnpm run dev
```

開發伺服器預設在 `http://localhost:5173`，並監聽所有網路介面（`server.host: true`），方便手機在同一網路下測試。

> **注意**：瀏覽器只允許在 `localhost` 或 HTTPS 下使用定位。用手機透過區網 IP（如 `http://192.168.x.x:5173`）開啟時無法使用 GPS 模式，只能測試隨機模式。

## 3. 指令一覽

| 指令 | 說明 |
|---|---|
| `pnpm run dev` | 啟動開發伺服器（含熱更新） |
| `pnpm test` | 執行全部測試一次 |
| `pnpm run test:watch` | 監看模式，檔案變更時自動重跑測試 |
| `pnpm run lint` | ESLint 程式檢查 |
| `pnpm run build` | TypeScript 型別檢查 + 正式建置，輸出至 `dist/` |
| `pnpm run preview` | 在本機預覽 `dist/` 的正式版 |
| `pnpm run update-brands` | 從 OpenStreetMap 重新統計品牌清單，見第 7 節（`--save 檔案` 保存原始資料、`--input 檔案` 離線重算） |

## 4. 環境變數

| 變數 | 必要 | 說明 |
|---|---|---|
| `VITE_CONTACT_EMAIL` | 建議 | 「免責聲明與常見問題」頁的權利人聯絡信箱。未設定時頁面顯示「聯絡信箱尚未設定」 |

- 本機開發與建置時請放在 `.env.local`（已列入 `.gitignore`，不會提交）。範本為 `.env.example`。
- 以 `VITE_` 開頭的變數會**在建置時寫入前端程式**，任何人都看得到。請勿放入密碼或金鑰。
- 建議使用專用的公務信箱，不要使用個人信箱。
- CI／CD 建置時，請在建置環境設定此變數，或在建置前產生 `.env.local`。

## 5. 測試

```bash
pnpm test
```

預期結果：

```
 Test Files  9 passed (9)
      Tests  85 passed (85)
```

- 測試環境為 jsdom，不需要瀏覽器與網路；定位、店家查詢、計時器皆以模擬方式測試。
- 測試範圍與案例說明見《系統設計說明書》第 13 節。
- 新增功能或修正錯誤時，請一併新增或更新測試。

**需人工驗證的項目**（自動化測試無法涵蓋）：

| 項目 | 驗證方式 |
|---|---|
| 畫面與動畫 | 手機與電腦瀏覽器實際操作，確認轉盤順暢、指針停在格子中間 |
| 真實定位與店家查詢 | 以 HTTPS 或 localhost 開啟，允許定位，確認出現附近店家 |
| 音效 | 開啟音效，轉動時有喀喀聲、停止時有叮咚聲 |
| 震動 | Android 手機的 Chrome，轉出結果時震動 |
| 地圖嵌入 | 結果卡片地圖正常顯示 |

## 6. 建置與部署

### 6.1 建置

```bash
pnpm run lint && pnpm test && pnpm run build
```

輸出結構：

```
dist/
├── index.html
└── assets/
    ├── index-<hash>.js
    └── index-<hash>.css
```

本系統為純靜態網站，可部署至任何靜態主機（Nginx、Apache、物件儲存 + CDN、Netlify、Vercel、GitHub Pages 等）。

### 6.2 部署必要條件

| 條件 | 原因 | 未符合時的現象 |
|---|---|---|
| **HTTPS** | 瀏覽器只允許在安全連線下使用定位 | GPS 模式一律顯示定位失敗 |
| **SPA 路徑回退** | 使用 HTML5 history 路由，`/settings`、`/about` 沒有實體檔案 | 直接開啟或重新整理 `/settings` 出現 404 |
| 網站路徑設定正確 | 預設部署在網域根目錄 `/` | 部署在子路徑時資源載入失敗；建置時以環境變數 `BASE_PATH` 指定，例如 `BASE_PATH=/drink/ pnpm run build` |

### 6.3 Nginx 設定範例

```nginx
server {
    listen 443 ssl http2;
    server_name drink.example.com;
    root /var/www/drink-spinner/dist;

    # SPA 路徑回退
    location / {
        try_files $uri /index.html;
    }

    # 檔名含 hash 的資源可長期快取
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # index.html 不快取，確保發布後立即生效
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    # 安全標頭（見 6.4）
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data:; connect-src https://overpass-api.de https://overpass.kumi.systems; frame-src https://www.openstreetmap.org https://www.google.com; base-uri 'self'; form-action 'self'" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Permissions-Policy "geolocation=(self), camera=(), microphone=()" always;
}
```

### 6.4 Content Security Policy 白名單

| 指令 | 允許來源 | 用途 |
|---|---|---|
| `script-src` | `'self'` | 建置後的 JS（無內嵌腳本） |
| `style-src` | `'self'`、`'unsafe-inline'`、`fonts.googleapis.com` | 樣式、轉盤動畫的 inline style、字型樣式表 |
| `font-src` | `fonts.gstatic.com` | 粉圓體字型檔 |
| `img-src` | `'self'`、`data:` | 網站圖示（data URI） |
| `connect-src` | `overpass-api.de`、`overpass.kumi.systems` | 查詢附近店家（主要與備援） |
| `frame-src` | `www.openstreetmap.org`、`www.google.com` | 結果卡片地圖 |

新增外部服務時，必須同步更新此白名單與《系統設計說明書》第 9 節。

### 6.5 部署到 GitHub Pages

儲存庫已內建自動部署流程 `.github/workflows/deploy.yml`：推送到 `master` 分支時，自動執行程式檢查、測試、建置並部署。

**首次設定**

1. 在 GitHub 建立儲存庫（免費方案的 GitHub Pages 需為公開儲存庫）。
2. 儲存庫 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
3. 儲存庫 **Settings → Secrets and variables → Actions → Variables** 新增：

   | 變數 | 必要 | 說明 |
   |---|---|---|
   | `VITE_CONTACT_EMAIL` | 建議 | 免責聲明頁的聯絡信箱 |
   | `BASE_PATH` | 否 | 覆寫網站路徑；使用自訂網域時設為 `/` |

4. 推送程式碼到 `master`，在 **Actions** 頁籤確認流程成功。

**網址與路徑**

| 儲存庫 | 網址 | 網站路徑（自動判斷） |
|---|---|---|
| 一般儲存庫，例如 `drink` | `https://<帳號>.github.io/drink/` | `/drink/` |
| `<帳號>.github.io` | `https://<帳號>.github.io/` | `/` |
| 設定自訂網域 | `https://自訂網域/` | 需設定變數 `BASE_PATH=/` |

**GitHub Pages 的限制**

- 不支援 SPA 路徑回退，流程以複製 `index.html` 為 `404.html` 處理。直接開啟 `/settings` 可正常顯示，但 HTTP 狀態碼為 404，不影響使用。
- 無法自訂回應標頭，6.4 節的 CSP 等安全標頭無法設定。正式對外服務建議改用可設定標頭的主機。
- 已提供 HTTPS，GPS 定位可正常使用。

### 6.6 部署後驗證

1. 開啟首頁、`/settings`、`/about`，以及直接重新整理 `/settings`，皆應正常顯示。
2. 允許定位後出現附近店家轉盤。
3. 轉一次，結果卡片地圖正常顯示。
4. `/about` 顯示正確的聯絡信箱。
5. 瀏覽器開發者工具主控台沒有 CSP 錯誤。

## 7. 每月品牌清單更新作業

設定頁「喜歡的品牌」與隨機模式使用的品牌清單（`src/data/brands.json`），為 OpenStreetMap 全台飲料店分店數前 20 名。

### 7.1 執行頻率與負責人

| 項目 | 內容 |
|---|---|
| 頻率 | 每月一次（建議每月第一個工作日） |
| 負責人 | （請填寫） |
| 預估時間 | 約 10 分鐘 |

> Overpass API 為公益服務，請勿頻繁執行或寫成高頻排程。

### 7.2 作業步驟

1. 取得最新程式碼並安裝套件。
   ```bash
   pnpm install
   ```
2. 執行統計腳本（約 1～3 分鐘）。
   ```bash
   pnpm run update-brands
   ```
   伺服器忙碌時腳本會自動重試（最多 3 次，間隔 30、60 秒）。
3. 檢查輸出的表格：
   - 前 20 名是否都是手搖飲品牌（不是咖啡廳、餐廳）。
   - 知名品牌店數是否與上月相近；明顯偏低通常是店名寫法沒比對到。
   - 「無法歸類品牌」的數量是否異常增加。
4. 如有品牌店數偏低或寫法未比對到，編輯 `scripts/update-brands.mjs` 的 `ALIASES`，補上品牌寫法：
   ```js
   '品牌統一名稱': { name: '顯示用短名', keywords: ['寫法一', '寫法二'] },
   ```
   為避免重複向伺服器查詢，可在步驟 2 加上 `--save` 保存原始資料，調整別名後用離線模式重算：
   ```bash
   pnpm run update-brands --save tw.json     # 步驟 2 改用此指令
   pnpm run update-brands --input tw.json    # 調整 ALIASES 後重算，不連網
   ```
5. 執行測試，確認清單格式、名次、關鍵字唯一性皆通過。
   ```bash
   pnpm test
   ```
6. 本機開啟設定頁，確認品牌清單與資料日期正確。
7. 提交 `src/data/brands.json`（以及有修改的 `scripts/update-brands.mjs`），提交訊息範例：`chore: 更新 2026-11 品牌分店數清單`。
8. 依第 8 節發布。

### 7.3 注意事項

- **關鍵字唯一**：同一個關鍵字不可同時屬於兩個品牌，否則測試會失敗。
- **授權標示**：`brands.json` 的 `license` 欄位必須保留「© OpenStreetMap contributors（ODbL）」，畫面會顯示此標示。
- **不引用第三方排行**：品牌清單只使用 OSM 自行統計，不從其他網站抓取排行，以避免著作權與使用條款爭議。
- **退回機制**：檔案格式錯誤時 App 會改用內建清單而不會中斷，但仍應以測試確保格式正確。

## 9. 故障排除

| 現象 | 可能原因 | 處理方式 |
|---|---|---|
| `pnpm run dev` 顯示埠號已被占用 | 已有另一個開發伺服器在執行 | 關閉舊的，或使用 Vite 自動改用的埠號（如 5174） |
| 線上 GPS 模式一律定位失敗 | 未使用 HTTPS，或 `Permissions-Policy` 禁止定位 | 改用 HTTPS；確認 `geolocation=(self)` |
| 重新整理 `/settings` 出現 404 | 主機未設定 SPA 路徑回退 | 依 6.3 節設定 `try_files` 或主機對應功能 |
| 店家查詢持續失敗 | Overpass 伺服器忙碌、CSP 擋住 `connect-src` | 檢查主控台錯誤；確認 CSP 白名單；稍後再試 |
| 地圖空白 | CSP 擋住 `frame-src`，或 Google 嵌入暫時失效 | 確認 CSP 白名單；隨機模式可改按連結開啟 Google 地圖 |
| 字型不是圓體 | Google Fonts 無法連線或被 CSP 擋住 | 確認 `style-src`、`font-src` 白名單；失敗時會使用系統字型，不影響功能 |
| 免責聲明頁顯示「聯絡信箱尚未設定」 | 建置時未設定 `VITE_CONTACT_EMAIL` | 設定後**重新建置**（環境變數在建置時寫入） |
| 設定頁品牌清單變成舊的 12 個品牌 | `brands.json` 遺失或格式錯誤 | 執行 `pnpm test` 查看錯誤；重新執行 `update-brands` 或從版本庫還原 |
| `update-brands` 出現 `Overpass 回應 504` | 伺服器忙碌，重試 3 次仍失敗 | 稍後（建議離峰時段）再執行 |
| 測試失敗：一個關鍵字屬於多個品牌 | `ALIASES` 中有重複關鍵字 | 移除其中一個品牌的重複關鍵字後重新統計 |

## 10. 變更管理

- 所有變更以合併請求（Pull Request）提交，至少一人審查後合併。
- 合併前必須通過第 8 節檢核表第 1～3 項。
- 下列變更須同步更新文件：

| 變更類型 | 需更新的文件 |
|---|---|
| 新增或修改功能、畫面 | 使用者操作手冊、系統設計說明書 |
| 新增或修改設定項目 | 使用者操作手冊第 6 節、系統設計說明書第 7.3 節 |
| 新增外部服務 | 系統設計說明書第 9、11 節、本手冊第 6.4 節（CSP） |
| 修改建置、部署或環境變數 | 本手冊 |
| 修改轉盤規則或演算法 | 系統設計說明書第 8 節 |

- 文件版本紀錄見 [文件總覽](./README.md)。
